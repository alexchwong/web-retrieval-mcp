# Configuration and tool contracts

[Back to README](../README.md)

The committed `docker-compose.yml`, `searxng/settings.yml`,
`searxng/limiter.toml`, and `web-retrieval/settings.toml` are the **active** files.
Their `.example` counterparts are reference copies, **not** files automatically
regenerated at startup. Only `.env` is created from `.env.example` by
`setup.sh`. Never commit `.env`: it holds the SearxNG secret.

## Startup settings (`.env`)

| Variable | Shipped default | Meaning |
|---|---|---|
| `SEARXNG_SECRET` | Generated by `setup.sh` | Secret for SearxNG; replace the placeholder before manually starting Compose. |
| `SEARXNG_BIND_ADDRESS` | `127.0.0.1` | Host address exposing SearxNG. |
| `SEARXNG_HOST_PORT` | `8888` | Host-side SearxNG port. |
| `SEARXNG_BASE_URL` | `http://localhost:8888/` | Public URL advertised to SearxNG; update if the host port changes. |
| `MCP_BIND_ADDRESS` | `127.0.0.1` | Host address exposing the MCP container. |
| `MCP_HOST_PORT` | `8765` | Host-side MCP port; the container still listens on 8765. |
| `MCP_SERVER_NAME` | `web-retrieval` | MCP server identity. |
| `UWSGI_WORKERS` | `2` | SearxNG worker count. |
| `UWSGI_THREADS` | `2` | SearxNG thread count. |

Compose also accepts `SEARXNG_IMAGE` (default `docker.io/searxng/searxng:latest`)
from its environment; the shipped `.env.example` does not define it.
The container's `MCP_HOST=0.0.0.0` means **inside** the container; its host
exposure remains controlled by `MCP_BIND_ADDRESS` in Compose.

After modifying host ports, bind addresses, environment wiring, or image
settings, use `docker compose up -d` so Compose can **recreate** affected
containers. `docker compose restart` alone does **not** apply changed port
mappings or environment configuration. Rebuilding the Python image requires
`docker compose up -d --build`.

## Research settings (`web-retrieval/settings.toml`)

These are the actual shipped file values; unspecified settings also have
built-in defaults in `web-retrieval/settings.py`.

| Setting | Shipped value | Effect |
|---|---:|---|
| `search.searxng_url` | `http://searxng:8080` | SearxNG URL **from inside** the MCP container. |
| `search.num_results` | `8` | Maximum SearxNG result URLs considered per search. |
| `search.timeout_seconds` | `10.0` | SearxNG request timeout (seconds). |
| `search.language` | `en` | Search language. |
| `search.safesearch` | `0` | Search filtering: 0, 1 or 2. |
| `fetch.concurrency` | `6` | Concurrent URL downloads in a search call. |
| `fetch.timeout_seconds` | `12.0` | Per-fetch timeout setting; **not** a hard whole-call deadline. |
| `fetch.max_bytes` | `20000000` | Maximum fetched response size per URL. |
| `fetch.max_document_chars` | `40000` | Extracted text cap per fetched document. |
| `fetch.max_pdf_pages` | `40` | PDF pages inspected at most. |
| `fetch.user_agent` | `web-retrieval/1.0` | Outbound HTTP User-Agent. |
| `chunk.words` | `350` | Approximate words per ranked passage. |
| `chunk.overlap` | `50` | Word overlap between neighboring passages. |
| `ranking.default_max_passages` | `8` | Passages requested if the tool caller omits `max_passages`. |
| `ranking.max_passages` | `20` | Upper limit for the tool's `max_passages` argument. |
| `ranking.max_passages_per_source` | `2` | Maximum returned passages per URL. |

An invalid edit is logged and the last successfully loaded settings are kept;
if the first load fails, the built-in defaults are used. The container mounts
the TOML file read-only **inside** the container; the host copy is editable.

### Live reload

Each `search_web` or `read_url` invocation retrieves one immutable settings
snapshot. The manager checks the settings file's **modification time in
nanoseconds and byte size**. A valid *detected* edit is used by that call,
without restarting the server. **Not every edit is guaranteed to be noticed**:
rapid same-length edits with an unchanged timestamp fingerprint may be missed.
Save again or restart the MCP container if a change does not take effect.
Some editors replace files atomically; the behavior of the bind-mounted file
with that editing method has not been verified.

For separate non-Compose execution, `MCP_SETTINGS_FILE` can select a different
TOML path. `MCP_HOST`, `MCP_PORT` and `MCP_SERVER_NAME` are read at process
startup and require a process restart to change.

## MCP tools: inputs, outputs and limits

### `search_web(query: str, max_passages: int | None = None)`

1. Search SearxNG, considering at most `search.num_results` eligible URLs.
2. Concurrently fetch their HTML or PDF contents. Failed downloads are skipped.
3. Extract text; split into overlapping word chunks and rank them lexically
   with BM25 against the query.
4. Return `{"passages": [...], "sources": [...]}`. Each passage contains
   `text`, `url`, `title` and BM25 `score`; each source contains `url`, `title`
   and SearxNG `snippet`.

The caller can set `max_passages` (clamped from 1 to
`ranking.max_passages`); the number returned can be **smaller** than requested,
including when diversity filtering removes items. If no documents are fetched,
there may be `sources` with no `passages` and a `note`. A SearxNG failure
produces an `error` with empty lists. A BM25 score is lexical relevance,
**not** factual confidence or source credibility.

### `read_url(url: str)`

Accepts a URL whose parsed scheme is `http` or `https`; fetches that single
address (following redirects) and returns `{"url": ..., "text": ...,
"chars": ...}` or an `error` dictionary. Only HTML/XML-like and PDF responses
are extracted. Fetch-byte, PDF-page and extracted-character caps apply. The
returned text is not guaranteed to be the full source or to preserve layout.

**Security:** there is currently **no check** for local, private, link-local or
cloud metadata IP addresses, either before the request or after redirects.
Only use with trusted local MCP clients; see [security](security.md).

## Using another SearxNG instance

`search.searxng_url` can point to a compatible existing SearxNG endpoint that
is reachable **from the MCP container**, with JSON search enabled. However,
changing TOML **does not disable** the bundled SearxNG service: `setup.sh`
starts the full Compose stack and `web-retrieval` declares a dependency on
`searxng`. A one-service Compose deployment is a separate setup and is **not**
provided by the current script. Do not assume `localhost` inside the MCP
container refers to a host-based SearxNG instance.

## Dependencies and supported Python versions

The Dockerfile uses **Python 3.12**. CI tests **Python 3.10 and 3.13** on
Linux and macOS, installing dependencies from
[`web-retrieval/requirements.txt`](../web-retrieval/requirements.txt). FastMCP
is pinned to **4.1.6**, whose Streamable HTTP API accepts the current
`stateless_http=True` startup call; it declares support for Python 3.10+.
Python 3.10 installs `tomli` as a conditional `tomllib` backport.
Other dependencies currently have minimum versions rather than a full lock,
so fresh builds can resolve newer releases. Do not assume every release of
these packages was tested. See [operations](operations.md#developer-tests-and-ci)
for the exact offline checks.
